# WMS 业务蓝图

## 1. 业务目标

WMS 的目标是把“货在哪里、数量多少、状态如何、谁在处理、何时完成”变成可追踪、可优化、可审计的数据闭环。Stone WMS 的第一阶段聚焦仓内执行，而不是 ERP、OMS、TMS 的全部能力。

## 2. 系统边界

### 上游系统

- ERP：主数据、采购订单、供应商、成本与财务过账。
- OMS：销售订单、取消订单、交付优先级。
- TMS：承运商、运单、路由、交接状态。

### WMS 内部核心

- 主数据：仓库、库区、库位、SKU、包装、批次、货主。
- 入库：ASN、收货、质检、上架。
- 库存：可用、冻结、占用、在途、批次、效期。
- 出库：订单释放、波次、拣货、复核、包装、发运。
- 库内：移库、补货、盘点、库存调整。
- 作业：任务分配、优先级、绩效、异常处理。

### 下游系统

- BI/报表：库存周转、库位热度、人员效率、缺货率。
- 设备：PDA、电子标签、输送线、称重、打印机。
- 消息通知：Webhook、MQ、站内信、短信/邮件。

## 3. 核心流程

### 入库流程

1. 接收 ASN 或手工创建收货单。
2. 到货登记，按 SKU/批次/包装收货。
3. 质检判定：合格、待处理、不合格。
4. 系统推荐上架库位。
5. PDA 执行上架，库存从暂存区转入存储位。
6. 回传 ERP 到货与库存变更。

### 出库流程

1. 接收销售订单或调拨出库单。
2. 校验库存可用量并执行库存占用。
3. 按优先级、承运商、区域生成波次。
4. 生成拣货任务，支持单品、多品、播种、边拣边分。
5. 复核、包装、称重、贴面单。
6. 发运交接，库存扣减并回传 OMS/TMS。

### 盘点流程

1. 创建全盘/动盘/循环盘点计划。
2. 冻结盘点范围或使用动态快照。
3. PDA 采集实盘数。
4. 生成差异，审核后调整库存。
5. 沉淀差异原因：错放、漏扫、破损、系统单据滞后。

## 5. MVP 范围

第一阶段只实现最小业务闭环：

- 入库增加库存。
- 出库扣减库存。
- 库存不足时拒绝出库。
- 查询 SKU 总库存、库位库存、库存流水。

该范围足以验证领域模型、API 习惯、测试策略和后续持久化演进方向。

## 6. 关键业务规则

1. 同一 SKU 可以分布在多个库位。
2. 每次库存增减必须产生库存流水。
3. 出库数量不得大于可用库存。
4. 当前出库按库位更新时间排序近似 FIFO，后续应改为批次/效期 FEFO 或策略引擎。
5. 单据号 `referenceNo` 贯穿库存流水，支持审计追踪。

## 7. 演进路线

- V0：内存 MVP，验证业务规则。
- V1：数据库持久化、基础主数据、OpenAPI、认证授权。
- V2：入库单/出库单状态机、任务体系、PDA API。
- V3：波次、补货、盘点、批次效期、库存占用。
- V4：事件驱动、设备集成、规则引擎、报表与可观测性。
