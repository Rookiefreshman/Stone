# 测试策略与用例设计

## 1. 测试目标

WMS 测试必须优先保护库存准确性、单据状态一致性、异常可追踪性。任何涉及库存增减的功能都必须具备自动化测试。

## 2. 测试金字塔

- 单元测试：领域对象、库存扣减、状态流转、规则引擎。
- 应用服务测试：入库、出库、盘点、补货等用例编排。
- API 测试：参数校验、错误码、响应契约。
- 集成测试：数据库事务、MQ 事件、Redis 缓存、外部系统适配。
- 端到端测试：典型仓库作业链路，控制数量，避免脆弱。

## 3. 当前已覆盖用例

| 用例 | 断言 |
| --- | --- |
| 入库 | SKU 标准化、总库存增加、生成 RECEIVE 流水 |
| 跨库位出库 | 按库位分配拣货、总库存减少、生成 SHIP 流水 |
| 库存不足 | 抛出业务异常且不扣减库存 |

## 4. MVP 应补 API 用例

1. `POST /api/v1/warehouse/receive`：合法请求返回库存汇总。
2. `POST /api/v1/warehouse/receive`：数量小于等于 0 返回 400。
3. `POST /api/v1/warehouse/ship`：库存不足返回 409。
4. `GET /api/v1/inventory/{sku}`：不存在 SKU 返回总量 0。

## 5. 业务验收用例

### 入库验收

- 给定 ASN-10001，SKU-001 到达 10 件，上架到 A-01-01。
- 当系统执行入库。
- 则 SKU-001 总库存为 10，A-01-01 库存为 10，库存流水包含 ASN-10001。

### 出库验收

- 给定 SKU-001 在 A-01-01 有 5 件，在 A-01-02 有 7 件。
- 当销售单 SO-20001 请求出库 8 件。
- 则系统生成两个拣货分配：A-01-01 5 件、A-01-02 3 件，总库存剩余 4 件。

### 异常验收

- 给定 SKU-001 总库存为 2。
- 当销售单请求出库 3。
- 则系统拒绝出库，返回库存不足，库存余额保持 2。

## 6. 后续测试增强

- 使用 Testcontainers 启动真实 PostgreSQL/MySQL。
- 使用 WireMock 模拟 ERP/OMS/TMS。
- 使用契约测试保护外部系统接口。
- 使用并发测试验证库存超卖防护。
- 使用性能基准测试评估库存扣减热点。
